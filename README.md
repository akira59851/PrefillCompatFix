# 预填充兼容修复（PrefillCompatFix）

修复 SillyTavern 中因模型不支持预填充导致的 `error 400: Requests ending with a model turn are not supported.` 报错，让请求能够正常发送。

支持 ST 原生请求与第三方插件发出的请求（第三方插件不保证 100% 覆盖）。

## 工作原理

在请求发送前自动检查内容。如果**当前使用的模型在生效名单内**，且**最后一条消息的角色不为 `user`**，插件就会在请求末尾静默追加一条用户消息（默认为零宽空格，可在设置中自定义）。

插件仅处理名单内且符合上述条件的请求，其余请求均保持原样，不作修改。若修复未成功，请求将按原样继续发送，插件不会阻断发送流程。

> **注意：** `Error 400`（错误请求）的触发原因有很多（如上下文超限、API 参数错误、空消息等）。本插件**仅针对“请求末尾角色非 user（预填充）”这一特定原因导致的 400 报错**，不涵盖其他类型的 400 错误。若启用插件后仍遇到报错，请结合控制台信息排查末尾角色或其他参数设置。

## 安装与使用

复制下方链接，在 ST 的「扩展」-「安装扩展」中粘贴并安装，完成后刷新页面即可：

`https://github.com/akira59851/PrefillCompatFix`

### 插件设置

打开 ST 的 **API 连接面板**（插头图标），在最底部找到「预填充兼容修复」（位于「查看隐藏的 API 密钥」右侧，移动端可能在下一行），点击即可打开设置面板。

- **自定义生效模型名单**：可自行添加或删除型号，每行填写一个（需与实际模型 ID 一致）。保存后即时生效，无需刷新页面。
- **名单同步机制**：插件更新内置模型名单时，列表会自动同步并在页面提示；你手动移除过的型号会保持关闭状态，不会自动恢复。
- **自定义补充内容**：默认使用零宽空格。若遇到其他插件过滤或特殊上游限制，可勾选并自定义追加的消息内容。

### 清理与调试

- **数据清理**：插件设置保存在 `extensionSettings.PrefillCompatFix` 中。SillyTavern 1.18.0 及以上版本支持在扩展管理界面直接使用「清理扩展数据」，或在卸载插件时勾选「同时清理扩展数据」。
- **调试模式**：将插件目录下 `index.js` 顶部的 `DEBUG_LOGS` 设置为 `true` 即可开启调试模式，浏览器控制台会输出详细的拦截与处理信息。

## 更新日志

### [v1.3.0] - 2026-11-17

- 新增「自定义补充消息内容」设置；默认补充内容由普通空格改为零宽空格，降低被其他插件误清理的概率。
- 内置模型名单新增 `gemini-4-carbon`、`gemini-4-hydrogen`、`claude-fable-5-2`；后续内置名单更新时将通过弹窗提示变更项。
- 支持 ST 1.18.0 的扩展数据清理功能。
- 优化底层请求拦截与正文解析逻辑，提升对不同数据格式的兼容性与稳定性。

### [v1.2.0] - 2026-10-18

- 新增模型清单设置入口，可直接在 ST 中自定义生效模型。

### [v1.1.0] - 2026-10-14

- 内置模型名单新增 `gemini-4-argon`。

### [v1.0.0] - 2026-10-11

- 首次发布。
- 支持在符合条件的请求末尾自动追加空格用户消息，修复部分模型的请求结尾兼容问题。
- 支持主页面及同源 iframe 中的请求，包括通过 `fetch`、XHR 及 jQuery `$.ajax` 等方式发出的请求。
- 内置 Gemini 与 Claude 系列模型名单。
